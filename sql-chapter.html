01 / Build the world

Data definition

DDL describes what relations are made of, how values behave, and which rules protect them.

01

SQL has several parts

DML queries and changes tuples. DDL specifies schemas and integrity constraints. SQL also includes view definition, transaction control, embedded and dynamic SQL, and authorization.

Domain types

char(n) is fixed length; varchar(n) is variable length. Numeric families include int, smallint, numeric(p,d), real, double precision, and float(n).

Integrity constraints

Use primary key, foreign key, and not null to keep invalid updates out of the database.

create table instructor (
  ID        char(5),
  name      varchar(20) not null,
  dept_name varchar(20),
  salary    numeric(8,2),
  primary key (ID),
  foreign key (dept_name) references department
);
Schema intuition: attributes define the columns, domains define valid values, and constraints define relationships that must remain true.
02 / Shape a result

Query structure

A typical query selects attributes from relations and keeps only tuples that satisfy a predicate.

02
select A1, A2, ..., An
from r1, r2, ..., rm
where P;

select

Chooses result attributes. SQL permits duplicates; use distinct to remove them. An asterisk means all attributes, and expressions can be renamed with as.

select distinct dept_name
from instructor;

from

Lists the relations involved. Multiple relations form a Cartesian product, which becomes useful when paired with matching conditions in where.

select name, course_id
from instructor, teaches
where instructor.ID = teaches.ID;

where

Filters rows with and, or, not, and comparisons such as <, <=, >, >=, =, and <>.

where dept_name = 'Comp. Sci.'
  and salary > 70000;
Aliases make self-joins readable. For example, compare instructor T with instructor S to find people earning more than someone in Computer Science. The keyword as is optional.
A relation can appear more than once with different aliases. This lets you follow an employee-supervisor relationship one step at a time.
03 / Refine the question

Additional operations

Patterns, ordering, ranges, and set operators add precision to everyday queries.

03

Pattern matching

% matches any substring and _ matches one character. Patterns are case sensitive.

select name
from instructor
where name like '%dar%';

Ordering

Sort with order by. Ascending is the default; use desc for reverse order. Multiple attributes can be listed.

order by dept_name, name desc;

Ranges and tuples

between includes both endpoints. SQL can also compare tuples when their shape matches.

where salary between 90000 and 100000;

Set operations

Combine compatible query results with union, intersect, and except. They remove duplicates automatically; append all to retain them.

(select course_id from section where semester = 'Fall' and year = 2017)
union
(select course_id from section where semester = 'Spring' and year = 2018);
04 / See the shape

Nulls & aggregates

Missing values have three-valued logic. Aggregate functions turn many rows into useful summaries.

04

Null is unknown

Arithmetic involving null returns null. Comparisons with null evaluate to unknown, and where treats unknown as false. Test explicitly with is null or is not null.

Five workhorses

avg, min, max, sum, and count operate over column values. count(*) counts tuples; count(column) counts values.

where vs having

where filters before groups form. having filters after aggregation.

select dept_name, avg(salary) as avg_salary
from instructor
group by dept_name
having avg(salary) > 42000;
Grouping rule: every attribute in select that is outside an aggregate must appear in the group by list.
05 / Ask inside the ask

Nested subqueries

A subquery is a select-from-where expression nested inside another query. It can live in from, where, or select.

05

Membership

in and not in compare a value to a subquery result.

where course_id in (
  select course_id from section
  where semester = 'Spring'
);

Some & all

some means at least one matching row. all means every row must match.

where salary > all (
  select salary from instructor
  where dept_name = 'Biology'
);

Exists

exists is true when a subquery is nonempty; not exists is true when it is empty. A correlated subquery refers to an outer alias.

where exists (
  select * from section T
  where S.course_id = T.course_id
);
A subquery in from acts like a temporary relation. The with clause gives a temporary relation a name, which is especially useful for multi-stage calculations.
A scalar subquery is used where one value is expected, such as counting instructors per department. It is a runtime error if it returns more than one tuple.
The unique construct evaluates true when a subquery contains no duplicate tuples.
06 / Change carefully

Modification

Insertion, deletion, and updates change stored tuples. Conditions and evaluation order matter.

06

insert

insert into course
values ('CS-437', 'Database Systems',
        'Comp. Sci.', 4);

Insert can also take the result of a select. That select is fully evaluated before rows are inserted.

delete

delete from instructor
where salary < (
  select avg(salary) from instructor
);

SQL first identifies qualifying tuples using the original average, then deletes them.

update

update instructor
set salary = case
  when salary <= 100000 then salary * 1.05
  else salary * 1.03
end;

Use case for conditional updates in one statement.

Remember: dropping a table removes the relation. Alter can add an attribute, assigning null to existing tuples; dropping attributes is not supported by many databases.
